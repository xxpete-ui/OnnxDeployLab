## 2. output0：不要把 shape 和语义混在一起

### 2.1 37 个通道分别是什么

结合当前模型的单类别配置及当前输出布局：

`37 = 4 个框坐标 + 1 个 bottle 分数 + 32 个 mask 系数`。

| 通道索引 | 内容 | 数值怎样使用 |
|---|---|---|
| 0 | cx | 网络输入坐标中的框中心 x |
| 1 | cy | 网络输入坐标中的框中心 y |
| 2 | w | 网络输入坐标中的框宽 |
| 3 | h | 网络输入坐标中的框高 |
| 4 | bottle 分数 | 用置信度阈值筛选 |
| 5～36 | 32 个 mask 系数 | 与 proto 加权组合，不当概率使用 |

当前布局没有额外的 objectness 通道，不能照搬其他 YOLO 导出的解析公式。这里的 37 和 32 是当前模型已核实的约定，不是所有分割模型的固定常数。

### 2.2 为什么是 channel × 8400 + candidateIndex

`[1,37,8400]` 的连续内存里，最后一维变化最快。对于 batch=1，先存通道 0 的 8400 个值，再存通道 1 的 8400 个值，依次排列。

因此，不是“一个候选的 37 个数连续放在一起”。正确公式是：

```cpp
predictions[channel * candidateCount + candidateIndex]
```

| 想读取什么 | 索引表达式 |
|---|---|
| 候选 i 的 cx | `0 * candidateCount + i` |
| 候选 i 的 cy | `1 * candidateCount + i` |
| 候选 i 的分数 | `4 * candidateCount + i` |
| 候选 i 的第 0 个 mask 系数 | `5 * candidateCount + i` |
| 候选 i 的第 k 个 mask 系数 | `(5+k) * candidateCount + i` |
| 候选 i 的第 31 个 mask 系数 | `36 * candidateCount + i` |

题目“索引为 10 的候选，第一个 mask 系数”正确答案是：

```cpp
predictions[5 * 8400 + 10]
```

`4 * 8400 + 10` 读取的是该候选的 bottle 分数。

## 5. 真实图片如何变成输入 Tensor

### 5.1 LetterBox 的目的

原图宽高比为 2:1。直接强行拉伸到正方形会改变物体形状。当前方法是等比缩放，再填充到固定 640×640。

实测参数：

| 项目 | 数值 |
|---|---:|
| 原图宽、高 | 2048、1024 |
| 网络输入宽、高 | 640、640 |
| scale | `min(640/2048,640/1024)=0.3125` |
| 缩放后宽、高 | 640、320 |
| 左、右 padding | 0、0 |
| 上、下 padding | 160、160 |
| 填充值 | BGR `(114,114,114)` |
| 缩放插值 | `cv::INTER_LINEAR` |

复习公式：

```cpp
scale = min(inputWidth / 原图宽, inputHeight / 原图高);
resizedWidth  = round(原图宽 * scale);
resizedHeight = round(原图高 * scale);

padLeft   = (inputWidth - resizedWidth) / 2;
padRight  = inputWidth - resizedWidth - padLeft;
padTop    = (inputHeight - resizedHeight) / 2;
padBottom = inputHeight - resizedHeight - padTop;
```

代码中除法需要浮点运算。保存左右上下各自的实际 padding，避免以后奇数差值时错误地假设两边完全相等。

本次使用的是固定 640×640 的 LetterBox；后续 Python 对齐也必须采用相同策略，不能默认 Python 会选择同样的 padding。

### 5.2 LetterBox 后还要做什么

| 阶段 | 数据 |
|---|---|
| imread 原图 | BGR、uint8、HWC、1024×2048 |
| LetterBox 图 | BGR、uint8、HWC、640×640 |
| cvtColor | RGB、uint8、HWC |
| convertTo /255 | RGB、float32、HWC，范围0～1 |
| 手动打包 | RGB、float32、CHW，shape `[1,3,640,640]` |

这里的 CHW 索引仍然是之前分类学过的公式：

```cpp
index = c * H * W + y * W + x;
inputData[index] = row[x][c];
```

不要把三个不同对象混起来：`image` 是原图；`letterboxImage` 是带灰边的网络图；`inputData` 是最终连续浮点数组。

Tensor 借用 `inputData` 的缓冲区。同步 Run 返回前，vector 需保持存活，且不能发生使数据无效的清空、扩容或并发改写。

### 6.2 从中心宽高转换为边界

```text
网络x1 = cx - w/2
网络y1 = cy - h/2
网络x2 = cx + w/2
网络y2 = cy + h/2
```

先在网络图里算框，再做逆变换：

```text
原图x = (网络x - padLeft) / scale
原图y = (网络y - padTop) / scale
```

顺序很重要：先去掉网络图中增加的边，再撤销缩放。

对于当前目标，原图框约为：


### 6.3 边界和整数框

- 先保留浮点边界，必要时再转整数。
- 用 `std::clamp` 限制在原图范围。
- 检查 `x2>x1`、`y2>y1`。
- 左上用 floor、右下用 ceil，构造覆盖该浮点区域的整数 ROI。
- 矩形右边界可以等于 width，下边界可以等于 height；直接访问像素时最大索引则为 width-1、height-1。
- `image.clone()` 后再画框，避免可视化改动影响后续原图处理。

## 8. NMS：10 → 1，并保留原始身份

### 8.1 NMS做什么

NMS按分数优先保留框，并抑制与已保留框重叠过大的其他候选。重叠通常用 IoU 衡量：

`IoU = 两框交集面积 / 两框并集面积`。

本次实验 NMS 阈值是0.45，与置信度阈值0.25含义不同：前者控制框重叠抑制，后者控制候选分数。两者都只是当前验证参数，生产配置和Python基准需明确统一。

当前只有 bottle 一个类别，因此本次可以直接对所有候选一起 NMS。未来多类别模型是否跨类别抑制，需要明确策略。

### 8.2 代码结构

按相同顺序从 candidates 提取 boxes 和 scores，调用：

```cpp
cv::dnn::NMSBoxes(
    boxes,
    scores,
    confidenceThreshold,
    nmsThreshold,
    keptIndices
);
```

`keptIndices` 是 boxes/candidates 内的位置，不是原始模型候选索引。

本次若保留位置为5，其对应关系是：

```cpp
candidates[5].predictionIndex == 3399
```

我们把保留的完整 SegCandidate 复制到 detections 中，后面继续使用 `detection.predictionIndex`，就不会丢掉原始身份。

实测：

```text
Candidates before filtering: 8400
Candidates above threshold: 10
Candidates after NMS: 1
Kept prediction index: 3399, score: 0.879162
```

这里说明后处理保留1个检测，不代表已经证明整张图实际只有1个物体。

## 10. proto与系数组合：得到160×160概率图

### 10.1 output1是什么

`output1=[1,32,160,160]` 可以理解为当前图片的一组32张原型特征图。不同实例使用不同系数来组合这组共享原型，得到各自的mask。

它不是直接输出32个最终实例mask，也不能把某张原型图当成单个物体的最终分割结果。

### 10.2 proto的内存索引

每张原型图有 `160×160=25600` 个值。

```cpp
planeSize = protoHeight * protoWidth;
pixelIndex = y * protoWidth + x;
protoIndex = k * planeSize + pixelIndex;
```

即：第k张原型图偏移 + 第y行偏移 + 第x列偏移。与此前CHW数组是相同的索引思路。

### 10.3 每个像素如何生成

对每个网格位置(y,x)：

```cpp
float logit = 0.0f;
for (std::size_t k = 0; k < maskChannels; ++k)
{
    logit += maskCoefficients[k] * proto[k * planeSize + pixelIndex];
}
```

这是32项乘积相加。矩阵形式可以写成：

```text
[1,32] × [32,25600] = [1,25600]
再整理为 [160,160]
```

当前先使用显式循环，让每次读取和相乘可追踪，尚未做性能优化。

### 10.4 为什么再用sigmoid

组合得到的 logit 不是0～1概率，需要通过 `sigmoid(z)=1/(1+exp(-z))` 得到mask概率。

当前代码按正负分支稳定计算：

```cpp
if (logit >= 0.0f)
{
    probabilityRow[x] = 1.0f / (1.0f + std::exp(-logit));
}
else
{
    const float expValue = std::exp(logit);
    probabilityRow[x] = expValue / (1.0f + expValue);
}
```

这两个分支数学等价，目的是避免直接计算很大的正指数。

这里对mask组合logit用sigmoid，与“当类别分数读成544时额外加sigmoid”不是一回事：前者是本阶段明确的数学步骤；后者会掩盖错误索引。

### 10.5 保存图片做了什么

```cpp
maskProbability.convertTo(maskPreview, CV_8U, 255.0);
```

它只是把0～1浮点概率转成0～255灰度以便观察，并没有二值化。保存PNG不是把浮点概率原样无损存档。

| 对象 | 类型/shape | 含义 |
|---|---|---|
| maskProbability | `CV_32FC1`，160×160 | 未裁剪的组合概率图 |
| maskPreview | `CV_8UC1`，160×160 | 为观察而量化的灰度图 |
| seg_mask_proto_3399.png | 单通道PNG | 当前阶段的可视化文件 |

后续计算继续使用 `maskProbability` 浮点数据，不应重新读取这张PNG来代替原始概率图。

| 网络输入图 | 640×640 | letterboxImage、networkBox |
| proto网格 | 160×160 | output1、maskProbability |

本次网络尺寸是proto尺寸的4倍。原图上下padding为网络图各160行，对应proto网格各40行的空间比例。这里只用于理解当前样本的几何关系，后续实现仍需依据真实尺寸计算，不写死4或40。

不要直接把160×160整幅概率图拉伸到2048×1024当作最终mask，因为网络图包含padding。也不能只去padding而不考虑检测框裁剪：组合概率图还没有被限定为框内实例区域。

后续需要选定一致的后处理基准，再确定crop、插值、去padding和阈值化顺序；这些操作并不随意可交换。当前记录不提前引入一套未经验证的实现。

## 13. 今天用到的C++知识，和算法对应起来复习

| C++知识 | 本次具体位置 | 要理解的点 |
|---|---|---|
| const指针 | predictions、proto | 借用ORT数据，不手动delete |
| vector | candidates、detections、系数 | 管理自有元素，保持顺序 |
| struct | SegCandidate | 把原始索引、分数、框绑定保存 |
| const引用遍历 | `for (const auto& detection : detections)` | 读取已有对象，不复制、不主动修改 |
| reserve | boxes/scores/detections | 预留容量，不会创建有效元素；仍需push_back |
| at | candidates.at(index) | 容器索引检查，防止把不同索引混用 |
| cv::Mat::ptr | 按行写概率图 | 获取该行地址，再按列访问 |
| clone | 可视化原图 | 深拷贝像素，避免修改原始图 |
| RAII | Ort对象、vector、Mat | 对象离开作用域时释放相应资源 |

重要的生命周期：

- `outputs[0]` 拥有预测缓冲区，`predictions` 只借用地址。
- `outputs[1]` 拥有proto缓冲区，`proto` 只借用地址。
- 当前循环内完成读取、组合、保存，要求outputs始终存活且未被移动或覆盖。
- `maskCoefficients` 是把32个数复制到vector里；`maskProbability` 是新分配并写入的Mat，均不是仅保存ORT内部指针。
- `detections` 当前保存的索引、分数和Rect2d都是值；真正回读mask系数时仍需要predictions有效。

## 14. 构建配置的本次结论

inspect_seg原来只依赖ORT，读图后加入OpenCV。相同目标的配置应合并：

```cmake
add_executable(inspect_seg src/inspect_seg.cpp)

target_include_directories(inspect_seg PRIVATE
    "${ORT_ROOT}/include"
    ${OpenCV_INCLUDE_DIRS}
)

target_link_libraries(inspect_seg PRIVATE
    "${ORT_ROOT}/lib/onnxruntime.lib"
    ${OpenCV_LIBS}
)
```

POST_BUILD中依次复制ORT DLL和对应Debug/Release的OpenCV DLL即可，不必把同一目标的include/link设置拆成多处重复维护。项目已有 `find_package(OpenCV REQUIRED)`；本次NMS头文件是 `opencv2/dnn.hpp`，现有OpenCV依赖已可支持。

这段是配置关系的复习摘要，不要求覆盖现有已运行的CMake文件，也不包含整个项目的全部配置。

## 17. 自检题与答案（现在不必全部做）

1. 为什么候选数用shape[2]而不是shape[1]？
2. 候选10的第一个mask系数是什么索引？
3. NMS返回5，能直接用5读取候选3399的系数吗？
4. 系数为-1.39319是不是错误？
5. mask预览是160×160，为什么不能直接拉伸回原图？
6. output1能否当成32个已完成的物体mask？

答案：

1. `[1,37,8400]`的第1维索引位置保存通道数37，第2维索引位置保存候选数8400；数组从0计数。
2. `5*8400+10`。
3. 不能；5是过滤后容器位置，需先取得`candidates[5].predictionIndex`，本次为3399。
4. 不是；系数不是概率，允许负值和大于1。
5. 它仍含网络图padding对应区域，也尚未按检测框限制实例范围。
6. 不能；它是共享原型，需要每个实例自己的32个系数组合。

复习目标不是背数字，而是能解释每个数字来自哪一维、每块内存由谁拥有、每个坐标属于哪张图。
